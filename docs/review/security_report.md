# Отчёт по безопасности и зависимостям

**Дата:** 25.11.2026  
**Категория:** безопасность / зависимости / фронтенд

## Найденные проблемы

| ID | Файл / строки | Приоритет | Риск | Исправление / рекомендация |
|---|---|---|---|---|
| SEC-01 | `app/blueprints/auth.py`, исходные строки 123–128 | Критично | Публичный `/register` принимал `role` из JSON. Клиент мог отправить `role="Администратор"` и создать учётную запись с привилегиями администратора. | Исправлено: публичная регистрация всегда назначает `Пользователь`; административное создание учётных записей должно быть отдельной авторизованной операцией. |
| SEC-02 | `web/user-dashboard.html`, исходные строки 97–104; `web/notes.html`, исходные строки 21–31 | Важно | Пользовательские `title_user` и `content` вставлялись в `innerHTML`. Если в заметке содержится HTML/JS, браузер может интерпретировать его как разметку (DOM XSS). | Исправлено: пользовательские поля создаются через DOM и записываются в `textContent`. |
| SEC-03 | `app/config.py`, исходные строки 53 и 59 | Критично для production | Использовались слабый пароль БД по умолчанию `12345` и известная строка по умолчанию для `SECRET_KEY`. | Исправлено: удалён пароль БД по умолчанию; ключ генерируется случайно для непроизводственной конфигурации; для `production` отсутствие `SECRET_KEY` вызывает ошибку запуска. |
| SEC-04 | `app/blueprints/auth.py`, маршрут регистрации | Важно | Публичная регистрация остаётся открытой. После исправления роли это не даёт права администратора, но может позволить массово создавать обычные аккаунты. | При необходимости отключить публичную регистрацию, добавить CAPTCHA/rate limit и аудит создания пользователей. |
| SEC-05 | `app/blueprints/auth.py`, маршрут `/login` | Рекомендация | После трёх неверных попыток выставляется постоянный `is_blocked`; поле `blocked_until` в модели не используется. | Реализовать временную блокировку с TTL и защиту от перебора по IP/учётной записи. |

## Зависимости
`requirements.txt` содержит Flask, Flask-SQLAlchemy, Flask-Login, Flask-Migrate, Werkzeug, Pillow, psycopg2-binary, python-dotenv и Alembic. Версии заданы нижними границами (`>=`), без lock-файла. Рекомендуется сформировать проверенный lock-файл и регулярно запускать `pip-audit`.

## Проверка
Bandit, pip-audit и динамическое тестирование безопасности не запускались в среде анализа. Указанные проблемы выявлены при статическом чтении исходного кода; исправления внесены в проект.
